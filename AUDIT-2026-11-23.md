## Medium

### M-1 Payer can void agent-signed vouchers the provider already holds — FIXED
- Location: `CallTab.setAgent`, signer check in `CallTab.redeem`.
- Impact: the provider serves calls against vouchers signed by the tab's agent and settles lazily (the point
  of the product). The payer can call `setAgent(id, 0)` (or any new key) and every unredeemed agent voucher
  instantly fails with `BadSignature`; the payer then closes and is refunded the provider's earnings. Loss =
  all unredeemed agent-signed value. Base has no public mempool, so the provider cannot race the rotation.
- Proof: `test_M1_agentRotationCannotVoidHeldVoucher` failed with `BadSignature` on the pre-fix code.
- Fix: the replaced agent stays a valid signer for one `challengeWindow` (`previousAgent`, `previousAgentUntil`).
  A second rotation of a non-zero agent during that grace reverts `AgentRotationPending`, so A→X→Y cannot cut
  the grace short; rotating to/from `address(0)` keeps the earlier grace.
- Regression: `test_fix_oldAgentRevokedAfterGrace`, `test_fix_secondRotationDuringGraceReverts`,
  `test_fix_rotateViaZeroCannotShortenGrace`, `testFuzz_fix_heldVoucherRedeemableWithinWindowAfterRevocation`.

### M-2 Pause lets the payer run out voucher deadlines (or freeze the provider indefinitely) — FIXED
- Location: `CallTab.pause`, paused check in `CallTab.redeem`.
- Impact: `pause` blocked `redeem` immediately and for as long as the payer liked. Vouchers carrying a
  `deadline` (the dapp offers one) expire while paused; the payer then closes, the provider can no longer
  redeem, and the refund goes to the payer. Without deadlines the provider's earnings are frozen until the
  payer chooses to close.
- Proof: `test_M2_pauseCannotRunOutVoucherDeadline` and `test_M2_pauseThenCloseAfterDeadline_...` failed with
  `TabPaused` on the pre-fix code.
- Fix: `pausedAt` is recorded; while `Open`, a pause blocks `redeem` only after `pausedAt + challengeWindow` —
  the same guarantee the close flow already gives. `unpause` clears it.
- Regression: `test_fix_pauseBitesAfterWindowAndUnpauseResets`, the fuzz test above (pause branch), and the
  updated `test_pauseBlocksRedeemUntilUnpause`.
- Trade-off for Lef: pause and agent rotation are no longer instant kill switches. A leaked agent key can be
  used for up to one challenge window, but only the tab's provider can redeem, and the period cap and the
  deposit still bound it. Pick a short challenge window and a period cap if that matters.

## Low (acknowledged, not changed)

- L-1 `redeem` period cap is a hard revert with no partial fill (`CallTab.redeem`). A provider holding only a
  voucher above the remaining room (e.g. after the payer starts close late in a period, window < period)
  cannot redeem any of it. Documented design; provider should redeem often or hold smaller vouchers.
  Shown by `test_L1_periodCapHardRevertInClosing`. Suggest a partial fill (`pay = min(owed, avail, room)`).
- L-2 USDC blacklist (`finalizeClose`, `redeem`). If the payer is blacklisted by Circle, `finalizeClose`
  reverts forever and the remainder is stuck; no alternate refund address.
- L-3 Unbounded `_tabsOfPayer` / `_tabsOfProvider`. Anyone can open 1-wei tabs to any provider and bloat
  `tabsOfProvider`, which can make that view too large for RPC calls. View-only; the dapp should page or index
  events.

## Info

- I-1 `expiry` is metadata only (documented); vouchers stay redeemable until close is finalized.
- I-2 No ERC-1271: smart-wallet payers must use an EOA agent key to sign.
- I-3 No check that `agent != provider`; setting it so lets the provider sign its own vouchers (payer footgun).
- I-4 Slither: `divide-before-multiply` in `_rollPeriod` is intentional flooring to period boundaries;
  `timestamp` comparisons are expected; `redeem` complexity noted. No other detectors fired.
- I-5 Test harness: running the whole unit suite against a Base fork (`make test-fork-base`) fails
  `test_wrongChainDomainRejected` (it switches to chain id 8453, which is already the fork's id) and the
  invariant setup (unfunded sender with Base base fee). Same on `main`; not a contract issue. Fork suites via
  `BASE_FORK_RPC` pass.

Refuted leads (tests in `AuditPoC.t.sol`): cross-tab / cross-chain voucher replay (tabId and chainId are
signed), signature malleability (OZ ECDSA), overpay or double redeem across cumulative vouchers (fuzz),
reentrancy (USDC, `nonReentrant`, state before transfer).
